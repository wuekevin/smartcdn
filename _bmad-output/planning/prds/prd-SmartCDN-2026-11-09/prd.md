## 1. 产品愿景

SmartCDN 是一套可私有化部署的商业级网络基础设施管理平台。它将多个 DNS 服务商、CDN 节点、SSL 证书体系以及分布式探针测速统一纳入一个后台，通过插件化 Provider 接口屏蔽服务商差异，让运营者可以在同一界面内完成所有 DNS 解析、CDN 配置、三网调度和证书生命周期管理。

平台核心主张：**真实能力驱动，安全变更优先，插件化无锁定**。系统对每个 Provider 的套餐限制精确建模，所有变更均需 Dry Run 预检和显式授权，DNS 发布内置 13 步安全流程与快照回滚。

目标用户解决的核心问题是：在中国互联网三网割裂、ICP 备案边界、Cloudflare SaaS 接入方式多样、SSL 证书分散于多平台的复杂环境下，实现统一自动化运营而不引入新的不可控风险。

## 2. 目标用户

### 2.1 用户角色

| 角色 | 描述 | RBAC 权限级别 |
|------|------|------------|
| **超级管理员（Super Admin）** | 系统部署者，完全控制，含系统配置和密钥管理 | 全部 |
| **DNS/CDN 运营管理员** | 负责 DNS 记录、CDN 配置、节点管理 | DNS、CDN、调度、SSL（操作） |
| **只读审计员** | 查看操作历史、告警记录、配置状态 | 全部模块只读 |
| **Probe/Node Agent（系统用户）** | 自动上报测速数据和节点状态 | Agent API 认证 Token |

### 2.2 Jobs To Be Done

**技术型站长（主要用户）：**
- 我需要在三网用户面前呈现最快的 IP，而不是凭感觉手动写死一个
- 我需要 SSL 证书自动续期，不想在某天发现网站因证书过期变成不安全
- 我需要在 Cloudflare 故障时能快速切到自有家宽节点，不依赖手动操作
- 我需要所有 DNS 操作都有历史快照，出错时能在五分钟内回滚
- 我需要对不同服务商的套餐限制有清晰理解，不想在 API 调用时才发现超过上限

**小型技术团队（次要用户）：**
- 我们需要对多个业务域名的配置变更有完整审计日志
- 我们需要 RBAC 保证不同角色只能操作授权范围内的资源
- 我们需要证书到期告警提前通知，不靠个人记忆

### 2.3 明确非用户（V1）

- 需要 Multi-Tenant SaaS 功能的托管服务提供商
- 只使用单一 DNS 服务商且不需要调度能力的用户（工具太重）
- 需要接入海外 CDN（BunnyCDN、Fastly）的用户（V2 路线图）

### 2.4 关键用户旅程

**UJ-1. 技术型站长首次接入 DNS Provider 并配置域名**
- **人物 + 场景：** Alex，管理 5 个域名，当前手动在阿里云 DNS 控制台操作，准备用 SmartCDN 统一管理。
- **入口状态：** 已完成 SmartCDN 安装向导，以超级管理员身份登录。
- **路径：** 进入「DNS 管理→DNS 服务商」→选择阿里云 DNS→填写 AccessKeyId/Secret→点击「验证连接」→系统调用 API 测试凭证并检测套餐能力→验证通过，账号状态变为「已连接」→进入「DNS 管理→域名管理」→添加域名 `jdmv.net`→绑定刚添加的阿里云账号→系统从 API 自动拉取现有 DNS 记录→展示对比视图（当前记录 vs 系统识别结果）。
- **关键时刻：** 系统展示"套餐能力报告"：当前套餐不支持分运营商线路，三网调度需要升级套餐或切换 Provider。Alex 了解了限制，决定先配置基础记录。
- **结束状态：** 域名已绑定，记录已同步，套餐能力已缓存，调度功能提示条件不满足。
- **边缘情况：** API 凭证错误→显示具体错误码和官方文档链接，不暴露密钥。

**UJ-2. 三网调度系统发现某节点性能下降，自动切换 IP**
- **人物 + 场景：** 自动化流程，无人工介入。系统检测到电信探针报告某 IP TTFB 超过 2000ms 连续 3 次。
- **路径：** 调度引擎计算综合评分→该 IP 评分跌破熔断阈值→从 Published Set 移除→从 Eligible Pool 选取备用 IP→校验新 IP HTTPS 可访问性→校验 Provider 套餐允许发布→获取分布式锁→执行 DNS 幂等更新→查询权威 DNS 确认变更→从外部检查 HTTPS→记录调度日志→若成功：解锁，发送告警"电信线路已切换至 IP X"→若失败：回滚至快照，发送告警"切换失败，已回滚"。
- **关键时刻：** 整个流程在下一个调度周期（默认 10 分钟）内自动完成，无需人工介入。
- **边缘情况：** Provider 限流→等待退避后重试；备用池为空→发送告警"电信线路无可用备用节点"，保持当前 Published Set 不变。

**UJ-3. SSL 证书到期前 30 天自动续期并部署到宝塔 Nginx + 阿里云 CDN**
- **人物 + 场景：** 自动化流程。系统检测到 `www.jdmv.net` 证书剩余有效期 ≤ 30 天，触发自动续期工作流。
- **路径：** 触发工作流执行→向 Let's Encrypt 创建 ACME Order→获取 DNS-01 Challenge→调用 DNS Provider API 创建 `_acme-challenge.jdmv.net` TXT 记录→轮询权威 DNS 确认 TXT 传播→通知 ACME 完成验证→下载新证书→验证证书链、SAN、私钥匹配→清理临时 TXT 记录→进入部署工作流→并行分支：(1) 部署到宝塔 Nginx（备份旧证书→写入临时目录→nginx -t→安全替换→reload→外部检查 HTTPS）；(2) 上传到阿里云 CDN（调用 CDN 证书更新 API→等待任务状态成功）→两个分支均成功→记录部署结果→发送成功通知。
- **关键时刻：** 整个流程无人工参与，证书在到期前完成更新，服务不中断。
- **边缘情况：** DNS 传播超时→重试 3 次，每次间隔 60 秒；Nginx reload 失败→回滚证书文件，发送告警要求人工介入。

**UJ-4. 管理员执行 DNS 迁移（阿里云 DNS → Cloudflare DNS）**
- **人物 + 场景：** Sam，准备将 `example.com` 从阿里云 DNS 迁移到 Cloudflare DNS。
- **路径：** 进入「DNS 管理→DNS 迁移」→选择域名 `example.com`→选择目标 Provider（Cloudflare）→系统执行迁移前检查：SOA、NS、DNSSEC、MX、TXT 完整性检查→生成迁移计划，显示将要在 Cloudflare 创建的记录列表→Sam 审查确认→系统在 Cloudflare 预同步全部记录→校验 Cloudflare 记录完整性→系统提示"请在域名注册商处将 NS 修改为 Cloudflare NS"→Sam 在域名注册商修改 NS→系统轮询监测 NS 委派变化→委派成功→标记迁移完成。
- **关键时刻：** NS 切换授权检查点——系统不会自动执行 NS 修改，只提供操作指引和状态监测。
- **边缘情况：** Cloudflare 记录同步不完整→阻止迁移，显示缺失记录列表，提示修复。

**UJ-5. 配置 Cloudflare SaaS Custom Hostname 接入 www.jdmv.net**
- **人物 + 场景：** Alex，希望通过 Cloudflare SaaS 为 `www.jdmv.net` 提供 Cloudflare CDN 加速。
- **路径：** 进入「CDN 管理→Cloudflare SaaS」→选择 Cloudflare 账号和 SaaS Zone→填写 Fallback Origin（`origin.wueym.com`）→系统验证源站 HTTPS 可访问性→填写 Custom Hostname（`www.jdmv.net`）→系统调用 Cloudflare API 创建 Custom Hostname，获取 DCV TXT 记录→系统展示"请在 jdmv.net 的 DNS 服务商处添加以下 TXT 记录完成域名验证"→Alex 确认并手动添加（或授权 SmartCDN 自动添加）→系统轮询主机名验证状态→验证通过，证书颁发→Alex 在 DNS 服务商配置 `www.jdmv.net CNAME edge.wueym.com`→网站通过 Cloudflare SaaS 分发。
- **关键时刻：** 系统清晰展示 Cloudflare SaaS 的接入边界：标准模式不提供 A 记录接入，须使用 CNAME，不支持的操作不出现在 UI 中。
- **边缘情况：** Fallback Origin 不可访问→阻止创建 Custom Hostname，提供诊断信息。

## 3. 术语表（Glossary）

| 术语 | 定义 |
|------|------|
| **DNS Provider** | 实现了统一 Provider 接口的 DNS 服务商适配器。阿里云 DNS、DNSPod、Cloudflare DNS 均为 DNS Provider。 |
| **CDN Provider** | 实现了统一 CDN 接口的 CDN 服务商适配器。Cloudflare、阿里云 CDN/ESA 均为 CDN Provider。 |
| **Deploy Target** | 实现了证书部署接口的部署目标适配器。宝塔 Nginx、原生 Nginx、SSH、阿里云 CDN 均为 Deploy Target。 |
| **Provider 能力（Capability）** | Provider 实例在当前套餐下支持的 API 操作和配置参数范围（如最小 TTL、分运营商线路支持）。不支持的能力返回 `UnsupportedCapability`，不静默忽略。 |
| **Zone** | DNS 托管区域，对应一个域名（如 `example.com`）在某个 DNS Provider 下的解析配置集合。 |
| **Domain（域名）** | SmartCDN 管理的一个二级域名实体（如 `jdmv.net`），可绑定多个 Zone（不同 Provider）。 |
| **DNS Record（DNS 记录）** | 一条 DNS 解析记录，包含类型（A/AAAA/CNAME/TXT 等）、主机名、值、TTL 和线路。 |
| **Record Set（记录集）** | 同一主机名、同一类型、同一线路下的多条 DNS 记录集合。 |
| **三网** | 中国大陆三大运营商：中国电信、中国联通、中国移动。 |
| **线路（Line）** | DNS Provider 支持的解析分流维度，如电信、联通、移动、境内默认、境外等。 |
| **Probe Agent** | 部署于特定网络节点（运营商/地区）的 Go 程序，负责定期对候选 IP 进行真实网络探测并上报结果。 |
| **Node Agent** | 部署于自有反向代理节点的 Go 程序，负责上报节点状态和执行授权的配置变更任务。 |
| **Candidate Pool（候选池）** | 某线路下所有已注册的候选 IP 集合，含未通过验证的 IP。 |
| **Eligible Pool（合格池）** | 通过 HTTPS 安全验证的候选 IP 集合。 |
| **Published Set（已发布集）** | 当前已实际发布到 DNS 的 IP 集合，受套餐记录条数上限约束。 |
| **Standby Pool（备用池）** | 合格但因套餐限制未发布的 IP，作为自动切换的备用来源。 |
| **Scheduling Run（调度执行）** | 一次完整的三网智能调度计算和 DNS 发布流程。 |
| **Publishing Job（发布任务）** | 一次针对某域名某线路的 DNS 记录更新操作，包含快照、锁、执行、验证和结果记录。 |
| **Rollback Job（回滚任务）** | 基于快照将 DNS 记录恢复到指定历史状态的操作。 |
| **Custom Hostname** | Cloudflare for SaaS 中，代表客户接入域名（如 `www.jdmv.net`）的配置实体。 |
| **Fallback Origin** | Cloudflare SaaS Zone 中用于回落的源站（如 `origin.wueym.com`）。 |
| **CNAME Target** | Custom Hostname 指向的 Cloudflare CDN 入口（如 `edge.wueym.com`）。 |
| **ACME** | 自动证书管理环境协议（RFC 8555），用于向 CA（如 Let's Encrypt）自动申请证书。 |
| **Certificate Order** | 一次 ACME 证书申请流程实体，包含域名列表、Challenge 记录和状态。 |
| **DNS-01 Challenge** | ACME 验证方式之一，通过在 `_acme-challenge.{domain}` 添加 TXT 记录证明域名控制权。 |
| **Certificate Workflow（证书工作流）** | 包含申请、验证、部署多个节点的 DAG（有向无环图）工作流实体。 |
| **DAG** | 有向无环图，证书工作流中描述节点执行顺序和依赖关系的结构。 |
| **ICP / 备案** | 中国工信部要求的互联网内容提供商备案制度。大陆境内 CDN 节点加速未备案域名违规。 |
| **Dry Run** | 模拟执行但不实际提交变更，用于预检和验证操作安全性。 |
| **Audit Log（审计日志）** | 所有用户操作和系统操作的不可变记录，包含操作者、操作对象、前后状态和时间戳。 |
| **RBAC** | 基于角色的访问控制（Role-Based Access Control）。 |
| **install.lock** | 首次安装完成后写入的锁文件，安装向导接口在此文件存在时进入锁定状态。 |

## 4. 功能需求

### 4.1 F1 — 项目基础架构与安装系统

**描述：** SmartCDN 的系统基础，包括初次启动的安装向导、应用配置、加密密钥管理和项目目录结构。安装向导完成后写入 `install.lock`，之后安装接口不可访问。实现 UJ-1 的前置条件。

**功能需求：**

#### FR-1: 安装向导环境检测

系统在首次启动（无 `install.lock`）时，自动检测并展示以下环境状态：Go 运行环境、MySQL 连接、Redis 连接、数据库权限、文件目录权限、端口占用、Nginx 可访问性、服务器时钟同步、加密密钥配置。

**可验收条件：**
- 检测结果逐项显示 PASS/FAIL/WARNING
- MySQL 连接失败时返回具体错误原因
- 任意 FAIL 项阻止进入下一步（非阻塞 WARNING 除外）

#### FR-2: 安装向导初始化流程

用户按顺序完成：数据库连接配置→Redis 配置→数据库 Migration 执行→创建管理员账号（密码复杂度强制）→设置应用加密密钥→配置后台访问地址→写入 `install.lock`→跳转至登录页。

**可验收条件：**
- 密码不符合强度要求时阻止提交并显示规则
- Migration 失败时显示错误日志，不写入 `install.lock`
- `install.lock` 写入后，`/api/v1/setup/*` 所有接口返回 403
- 不允许使用预设默认密码（如 `admin123`）

#### FR-3: 应用加密密钥管理

系统 API 凭证和证书私钥使用 AES-256-GCM 加密，密钥从环境变量 `SMARTCDN_ENCRYPT_KEY` 读取，不存在于代码或数据库中。

**可验收条件：**
- 环境变量未设置时，启动失败并输出明确错误信息
- 加密密钥不出现在日志、HTTP 响应或错误消息中
- 更换密钥后，系统提供重新加密存量数据的迁移脚本

#### FR-4: 结构化日志

所有服务端日志以 JSON 结构化输出，包含字段：`timestamp`、`level`、`module`、`request_id`、`message`、`error`（非空时）。

**可验收条件：**
- 日志中不出现任何明文 API Key、Secret、私钥、会话 Token
- 生产环境默认日志级别 `info`，可通过环境变量调整

### 4.2 F2 — 用户认证与 RBAC

**描述：** 管理员账号体系，支持登录、会话管理、RBAC 权限控制和操作审计。

**功能需求：**

#### FR-5: 用户认证

用户以用户名+密码登录，系统返回 JWT。支持登录失败限速（连续 5 次失败锁定 15 分钟）。

**可验收条件：**
- JWT 过期时间可配置，默认 24 小时
- 登录失败锁定提示剩余时间，不暴露锁定原因是密码错误还是账号不存在

#### FR-6: RBAC 权限控制

系统预置角色：超级管理员、DNS/CDN 运营管理员、只读审计员。角色可自定义，权限粒度至 API Endpoint 级别。

**可验收条件：**
- 越权 API 调用返回 403 而非 404（不泄露资源存在性）
- 权限变更实时生效，不需要重新登录

#### FR-7: 审计日志

所有涉及资源变更的操作（DNS 记录修改、凭证更新、调度执行、证书部署）自动写入不可变审计日志。

**可验收条件：**
- 记录字段：操作者 ID、操作类型、目标资源、IP 地址、时间戳、操作前后状态摘要
- 审计日志不支持删除（无软删除）
- 审计日志支持按操作者、时间范围、操作类型筛选

#### FR-8: CSRF 和 XSS 防护

API 层实现 CSRF Token 验证；后端对输入进行严格校验，HTTP 响应头包含 `X-Content-Type-Options`、`X-Frame-Options`、`Content-Security-Policy`。

### 4.3 F3 — DNS Provider 插件框架

**描述：** 核心插件接口定义，所有 DNS Provider 适配器必须实现此接口。接口版本化，新增 Provider 不修改调度层代码。实现 UJ-1 和 UJ-2 的技术基础。

**功能需求：**

#### FR-9: Provider 统一接口

每个 DNS Provider 必须实现以下接口方法：
`ValidateCredentials`、`DetectCapabilities`、`ListZones`、`ListRecords`、`CreateRecord`、`UpdateRecord`、`DeleteRecord`、`EnableRecord`、`DisableRecord`、`GetNameservers`、`GetLimits`、`VerifyPropagation`。

**可验收条件：**
- 不支持的方法返回 `UnsupportedCapabilityError`，不返回 nil 或静默 panic
- Provider 接口有版本字段，调度层在加载 Provider 时校验版本兼容性

#### FR-10: Provider 能力检测

调用 `DetectCapabilities` 后，系统缓存该账号的能力档案（套餐类型、支持线路、最小 TTL、同记录集上限、是否支持权重、API 限流参数）。

**可验收条件：**
- 能力档案在 UI 中可见（账号详情页展示套餐能力）
- 超过套餐限制的操作在 UI 层提前拦截，不发起 API 调用
- 能力档案有 TTL，可手动触发刷新

#### FR-11: Provider API 限速控制

每个 Provider 适配器内置 API 限速保护（令牌桶或滑动窗口），超限时本地排队重试，不抛出未处理异常。

**可验收条件：**
- 限速参数可由 Provider 适配器自行声明，管理员可覆盖
- 限速事件写入调试日志

### 4.6 F6 — DNS 迁移与记录发布引擎

**描述：** 支持域名在不同 DNS Provider 之间迁移（模式 B），以及将记录更新安全发布到权威 DNS 的核心引擎（13 步安全流程）。实现 UJ-4。

**功能需求：**

#### FR-20: DNS 迁移工作流（模式 B）

迁移流程：发现现有记录→生成迁移计划→预同步新 Provider→检查记录完整性（SOA/NS/DNSSEC/MX/TXT）→展示对比视图→人工审批 NS 切换→监测委派变化→迁移完成。每步有明确授权检查点，NS 切换步骤必须人工确认。

**可验收条件：**

- 系统不自动执行 NS 修改，只提供指引和状态监测

#### FR-21: Multi-DNS 模式（模式 C）

作为独立高级功能，要求多个权威服务商正确协同。系统必须在启用前检查：记录同步一致性、委派配置、DNSSEC 状态、故障恢复条件。检查不通过时阻止启用并显示具体缺失条件。

**可验收条件：**
- Multi-DNS 模式在 UI 上有明确提示"高级功能，启用前请阅读文档"
- 一致性检查以可视化对比表展示多 Provider 记录差异

#### FR-22: 13 步 DNS 安全发布

DNS Publishing Job 执行顺序：(1) 探针测速 (2) 计算评分 (3) 选择候选 (4) 校验 HTTPS (5) 校验 Provider 能力 (6) 生成 DNS 差异 (7) 保存当前快照 (8) 获取分布式锁 (9) 执行幂等更新 (10) 查询权威 DNS (11) 验证 HTTPS (12) 记录结果 (13) 失败执行安全回滚。

**可验收条件：**
- 任意步骤失败时，步骤 (13) 自动触发，回滚至步骤 (7) 的快照
- 分布式锁 TTL 不超过 60 秒，超时自动释放
- 发布操作支持 Dry Run（执行至步骤 (6) 生成差异后停止）

### 4.7 F7 — 分布式测速探针系统

**描述：** 独立的 Go Probe Agent，部署于真实运营商网络节点，采集多维网络指标。探针不能以修改请求头等方式伪造网络身份。

**功能需求：**

#### FR-23: Probe Agent 部署与注册

**可验收条件：**

### 4.8 F8 — 三网智能调度系统

**描述：** 基于探针数据的可配置评分算法，安全自动地为三网各线路选择最优 IP 集合并发布到 DNS。实现 UJ-2。

**功能需求：**

#### FR-26: 综合评分算法

评分公式：`Score = w1×Success + w2×Latency + w3×TTFB + w4×Throughput + w5×Stability`，权重可在后台配置。评分基于滑动时间窗口，支持异常值排除。

**可验收条件：**
- 权重配置实时生效，不需要重启服务
- 滑动窗口长度可配置（默认 60 分钟）
- 评分历史可查

#### FR-27: 调度安全机制

调度系统必须实现：节点冷却时间（新节点或刚恢复节点的保护期）、切换滞后阈值（防止评分小幅波动触发切换）、连续失败熔断（同一域名连续切换失败 N 次后暂停自动调度并告警）、防频繁切换保护（两次切换最小间隔可配置）。

**可验收条件：**
- 自动调度暂停时，管理员可手动解锁
- 切换决策记录完整（为何选择此 IP、为何排除彼 IP）

#### FR-28: 候选池与发布约束

候选池（Candidate Pool）→合格池（Eligible Pool，通过 HTTPS 验证）→已发布集（Published Set，不超过套餐上限）→备用池（Standby Pool）。每次调度时，Published Set 变更须经完整 Publishing Job（FR-22）。

**可验收条件：**
- Published Set 条数不超过当前 Provider 套餐的同记录集上限
- 合格池为空时，系统保持当前 Published Set 不变并发送告警
- 灰度发布模式：先修改单一线路，验证成功后推广其他线路

#### FR-29: 调度手动控制

管理员可：手动锁定某线路使用指定 IP（绕过自动调度）、手动触发调度、临时暂停某域名的自动调度、查看候选池和评分历史。

**可验收条件：**
- 手动锁定标记在 UI 中醒目展示，不被自动调度覆盖
- 手动操作写入审计日志

### 4.11 F11 — SSL ACME 证书管理

**描述：** ACME 协议（RFC 8555）证书全生命周期：申请（单域名/SAN/泛域名）、自动续期、ACME 账号管理。DNS-01 和 HTTP-01 验证均支持。私钥加密存储。

**功能需求：**

#### FR-36: ACME 账号管理

支持注册多个 ACME 账号（Let's Encrypt 生产/测试、ZeroSSL 等），账号与 CA 类型关联，支持账号停用。

**可验收条件：**
- Let's Encrypt 和 ZeroSSL 两个 CA 在 V1 中支持
- ACME 账号注册使用用户邮箱，注册成功后不再要求重新输入

#### FR-37: ACME DNS-01 验证

验证流程：创建 ACME Order→获取 Challenge→通过绑定的 DNS Provider 创建 TXT 记录→检查权威 DNS 传播（`VerifyPropagation`）→通知 ACME 完成验证→下载证书→清理临时 TXT 记录→触发部署工作流。支持并发多个 Challenge（同域不同记录），清理时只删除当前 Challenge 的 TXT 值。

**可验收条件：**
- 并发申请同一域名的主域名证书和泛域名证书时，系统正确处理两条不同值的 `_acme-challenge` TXT 记录
- TXT 记录传播检查失败后（超过重试上限），清理记录并标记订单为 FAILED
- DNS-01 支持 `_acme-challenge` 委派（配置将验证 TXT 委派到另一域名的 DNS Provider）

#### FR-38: ACME HTTP-01 验证

提供可选的 HTTP-01 验证路径，自动在指定 Nginx 配置中添加 `/.well-known/acme-challenge/` 路由。处理 CDN 缓存绕过和 Cloudflare 代理场景。

**可验收条件：**
- CDN 场景（包括 Cloudflare 代理开启时）默认优先使用 DNS-01
- HTTP-01 仅在 DNS-01 不可用时作为备选（需手动选择）
- HTTP-01 验证失败提供具体诊断（Cloudflare 代理？CDN 缓存？源站路由？）

#### FR-39: 自动续期

系统每天检查证书剩余有效期，在到期前 30 天触发自动续期工作流（优先查询 ACME ARI 确定 CA 推荐续期窗口）。支持重试（指数退避，最多 10 次），CA 限流时暂停并等待。

**可验收条件：**
- 续期成功率指标可在证书监控页查看
- 续期失败告警在第一次失败后立即发送，之后按重试间隔递减告警频率
- 手动触发续期可绕过续期窗口检查

### 4.12 F12 — SSL 多平台证书部署

**描述：** Deploy Target 插件接口，V1 支持 6 个部署目标：宝塔 Nginx、原生 Nginx、SSH 远程服务器、Cloudflare 证书场景、阿里云 CDN、阿里云 ESA。

**功能需求：**

#### FR-40: Deploy Target 统一接口

每个 Deploy Target 实现：`ValidateConnection`、`Deploy`（含前置检查和回滚逻辑）、`Verify`（外部检查部署结果）、`Rollback`、`GetStatus`。

**可验收条件：**
- Deploy 失败后自动调用 Rollback
- Verify 从外部（非本机）检查 HTTPS 证书，不仅靠本地文件检查

#### FR-41: Nginx 证书部署安全流程（9 步）

宝塔 Nginx / 原生 Nginx 部署：(1) 检查证书链 (2) 检查 SAN 覆盖目标域名 (3) 检查证书与私钥匹配 (4) 备份旧证书文件 (5) 写入临时目录 (6) 校验文件权限 (7) `nginx -t` 配置测试 (8) 安全替换证书文件 (9) `nginx -s reload`→外部检查 HTTPS→成功确认或失败回滚。

**可验收条件：**
- 步骤 (7) 失败时，不执行步骤 (8)，直接清理临时文件并返回失败
- 旧证书备份文件保留可配置天数（默认 7 天）
- 外部 HTTPS 检查从至少 1 个外部 IP 执行（非本机）

#### FR-42: 云 CDN 证书部署

阿里云 CDN 和 ESA 证书部署通过各自 API 实现，区分两个产品的不同接口。部署后轮询任务状态至完成/失败。

**可验收条件：**
- 阿里云 CDN 和 ESA 分别是两个独立的 Deploy Target 适配器
- 云端部署失败时，记录 API 返回的错误详情，不可回滚到旧证书（云端证书由云厂商管理）时标记为 FAILED 并告警

### 4.13 F13 — SSL 可视化工作流引擎

**描述：** DAG 工作流引擎，支持申请→验证→部署→通知的可视化编排。实现 UJ-3 的可视化版本，支持并行分支、条件判断和失败重试。

**功能需求：**

#### FR-43: 工作流节点类型

支持节点类型：开始、申请证书、DNS 验证、HTTP 验证、导入证书、校验证书、部署证书、条件判断（成功/失败分支）、并行分支、等待（固定时长/外部事件）、Webhook、通知、回滚、结束。

**可验收条件：**
- 并行分支节点支持"全部成功继续"和"任意失败立即回滚"两种策略
- 条件判断节点支持：证书剩余天数 < N、部署目标类型、前序节点结果

#### FR-44: 工作流执行与监控

工作流支持：定时触发（cron）、手动触发、自动续期触发。执行状态实时展示（节点高亮当前执行位置）。执行历史可查（节点级别日志、输入输出参数）。支持暂停、继续、取消和失败重试（从失败节点重试）。

**可验收条件：**
- 执行日志中展示每个节点的执行耗时和结果摘要
- 失败节点重试时，前序已成功节点不重复执行（幂等设计）
- 工作流执行记录不可删除（审计目的）

#### FR-45: 工作流版本管理

工作流支持保存历史版本，可对比版本差异，可回滚到历史版本。

**可验收条件：**
- 版本切换需要确认（告知当前是否有运行中的执行）
- 历史执行记录关联对应的工作流版本 ID

### 4.14 F14 — 监控中心与告警

**描述：** 覆盖 DNS、CDN、节点、SSL、系统健康的全面监控，支持告警规则配置和多渠道通知。

**功能需求：**

#### FR-46: 监控指标采集

监控范围：DNS 解析结果（实际 IP）、当前权威 NS、三网 HTTPS 成功率趋势、节点可用性、源站 TTFB、TLS 握手时间、SSL 有效期、证书部署状态、调度任务健康、MySQL/Redis/CPU/内存/网络吞吐量。

**可验收条件：**
- DNS 解析结果监控每 5 分钟从至少 3 个地区查询一次（可配置）
- 监控数据保留时间可配置（默认 90 天），超过后按策略压缩/删除

#### FR-47: 告警规则与通知

支持配置告警规则：指标名称、阈值条件、连续触发次数、告警等级（INFO/WARNING/CRITICAL）。支持告警静默窗口、去重、恢复通知、告警确认。

**可验收条件：**
- 告警历史按等级、时间、域名筛选
- 告警去重：同一规则在未恢复前只发送一次，恢复后发送恢复通知

#### FR-48: 告警通知渠道

V1 支持：Telegram Bot、SMTP 邮件、Webhook（HTTP POST，支持自定义 JSON 模板）。V2 路线图：企业微信、飞书、钉钉。

**可验收条件：**
- 通知渠道配置支持测试发送（发送一条测试消息）
- Webhook 支持自定义请求头和 JSON 模板（含可用变量列表）

#### FR-49: 自动故障处理

系统在检测到以下情况时自动执行对应动作：节点连续探测失败→从 Eligible Pool 摘除→触发调度切换；API 凭证失效→暂停相关操作→发送告警；发布任务失败→执行回滚→发送告警；证书部署失败→回滚旧证书（Nginx 场景）→发送告警。

**可验收条件：**
- 多个控制器不允许同时对同一域名执行 DNS 变更（分布式锁保证）
- 自动熔断：30 分钟内同一域名发生 3 次自动切换时，暂停自动调度并告警要求人工介入

## 8. 系统约束与护栏

### 8.1 现网保护（强制）

以下操作**严禁**未经授权执行：

| 操作 | 保护机制 |
|------|---------|
| 切换任何域名的 NS 记录 | 独立授权确认步骤，不可在批量操作中执行 |
| 删除未由 SmartCDN 托管的 DNS 记录 | 系统标记为"外部记录"，拒绝删除 |
| 修改 www.jdmv.net 的 Cloudflare 代理状态 | UI 中显示"首个业务域名保护"提示，需二次确认 |
| 替换任何域名的现有 SSL 证书 | 仅在证书部署工作流执行后替换，部署失败自动回滚 |
| 修改 static.01233.xyz / cdnapi.01233.xyz 的阿里云加速配置 | 标记为"敏感资源"，修改需超级管理员权限 |

### 8.2 ICP 备案边界（强制）

| 约束 | 说明 |
|------|------|
| www.jdmv.net（未备案） | 不能配置中国大陆境内 CDN 节点为加速入口；只能走 Cloudflare 或境外节点 |
| 自有节点接入大陆 CDN | 未备案域名不能使用需要 ICP 准入的加速服务 |
| 系统识别 | Provider 适配器能力检测时须区分"境内加速"和"全球加速"，对未备案域名禁用境内加速选项 |

### 8.3 DNS TTL 传播约束

DNS 变更不立即全网生效。系统在 UI 中不得宣称 DNS 修改后"立即生效"，必须展示 TTL 预估生效时间。自动调度的评分在 DNS 修改后需等待至少一个 TTL 周期再评估效果。

### 8.4 Cloudflare SaaS 接入约束

标准 Custom Hostname 仅支持 CNAME 接入，A 记录接入需 Cloudflare 付费功能授权。系统 UI 在无授权账号下不展示 A 记录接入选项。

### 8.5 探针真实性约束

Probe Agent 必须真实部署于对应网络环境，禁止通过修改 `User-Agent`、HTTP Header 或代理标签伪造运营商身份。系统在 Agent 注册时记录实际 IP，ISP 标识由运营商 IP 段数据库验证（允许误差，但不允许主动伪造）。

## 10. 成功指标

**SM-1（DNS 发布可靠性）：** DNS Publishing Job 成功率 ≥ 99%（排除 Provider 侧故障）。验证 FR-22。

**SM-2（调度响应时间）：** 节点性能下降（探针评分跌破熔断阈值）到完成 DNS 切换的时间 ≤ 2 个调度周期（默认 ≤ 20 分钟）。验证 FR-26、FR-27。

**SM-3（证书续期成功率）：** SSL 证书自动续期成功率 100%（排除 CA 侧故障和 DNS 传播超时）。验证 FR-39。

**SM-4（部署覆盖度）：** V1 交付时，全部 6 个 Deploy Target 在标准测试环境中均通过 L2（测试环境验证）。验证 FR-40、FR-41、FR-42。

**SM-5（插件扩展性）：** 新增第 4 个 DNS Provider（如华为云 DNS）所需代码修改不涉及 `internal/scheduler` 核心调度包。验证 FR-9。

**SM-6（现网零事故）：** 开发和测试期间，www.jdmv.net 及其他生产域名零未授权配置变更。验证 §8.1。

**反指标（不优化）：**
- **SM-C1（切换频率）：** DNS 切换次数不作为成功指标，过频切换损害用户体验。
- **SM-C2（功能覆盖率）：** 功能点数量不代表质量，不以"实现了多少功能"衡量。

7. 分布式 Probe Agent 的运营商 IP 验证数据库选型（IP2Location、MaxMind 等，许可证和精度对比）。

## 12. 假设索引

- **A-1（§4.3）：** DNS Provider 接口版本化能力假设基于 Go interface + 版本字段实现，不需要外部插件机制（非动态加载 `.so`）。
- **A-2（§4.9）：** Cloudflare for SaaS 的 Custom Hostname 计费按主机名数量，SmartCDN 展示计费说明但不代为支付。

- **A-4（§4.16）：** 宝塔 Go 项目部署的 P0 目标基于宝塔 Linux 面板版本 ≥ 7.9（Go 项目管理模块）。
